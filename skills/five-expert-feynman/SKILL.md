# 费曼循环（Feynman Loop）

`five-expert-panel` 技能组的第九棒。与第八棒是搭档：

| | `five-expert-interview` | 本技能 |
|---|---|---|
| 方式 | 出题拷问 | 你讲我听 |
| 找出盲区靠 | 你答错的地方 | 你**跳过去**的地方 |
| 适合 | 学完验收 | 学一半卡住、感觉“好像懂了” |

费曼法的全部力量在一步：**把东西用自己的话讲出来**。看着原文点头不算，讲不顺的地方就是没懂的地方，一个都藏不住。这个技能的任务是当那个听众，并且在你讲不顺的地方停下来，不走过去。

## When to Use（何时用）

- 用户说“用费曼法”“讲给我听，就当我 12 岁”“我好像懂了但说不清”
- 学完一个概念想验证是不是真懂（尤其是抽象概念：复利、机会成本、熵、梯度）
- 准备把某个东西教给别人、写文章、做汇报

不适用：用户连基础都没有（先学一轮再用本技能磨）；或者只是要一个定义（直接给）。

## 交互协议

这是对话式技能，节奏比内容重要：

1. **先讲，再等**。讲完 12 岁版，停下来，让用户复述。不替他总结，不给答案提示。
2. **一轮只处理一件事**。你复述→我诊断→我只补漏洞→你再复述。不建议一次堆三个要求。
3. **不提前进入新内容**。用户没把这个讲顺，就不开下一层。用户想跳，就说：“先把这个讲顺，跳过去的部分会变成坑。”
4. **不替用户填空**。他说到一半停了，不要接上他的句子（那是你在讲，不是他在讲）。可以问：“下一句是什么？”
5. **记录轮次与漏洞**。每轮存下：本轮发现的漏洞清单、已修复哪几条。最后汇总用。

## 第一轮：讲给 12 岁

不是“幼稚化”，是**把所有未解释的术语拿掉**。具体标准：

- 每个新词第一次出现，必须有一个日常对应物（“利率，就是借钱的人还你的租金”）
- 一句话只说一个意思，长句拆短
- 不用“因此”“综上”“本质上”这类词掩盖跳跃——它们经常就是漏洞本身
- 必须给**至少一个具体例子**（有数字/有人/有时间的那种）
- 必须给**一个反例或边界**：“但如果 X，这个说法就不成立”——没有边界的解释是错的解释

**关于类比的一个重要约束**：类比必须说明哪里像、**哪里不像**。只给一个“水管比电流”就拿走，用户会带着错误的直觉跑到很远。宁可多一句“但水管里的水会流光，电荷不会”。

篇幅：一轮讲解控制在一屏内（约 250–400 字）。太长就变成讲义，用户会跳过复述环节。

然后只问一句：“现在用你自己的话讲给我听，说错没关系，我要找的是你卡住的地方。”

## 诊断：三个病灶，必须引原句

用户复述后，逐句找这三类问题。**诊断不许笼统**——“不够清楚”“逻辑不完整”这种反馈等于没反馈。每条必须引用他的原句并指到具体位置。

| 病灶 | 长相 | 怎么抓 |
|---|---|---|
| **含糊** | 用了未定义的词、占位词（“这个东西”“某种机制”）、模糊量词（“很多”“比较好”） | 把句中的抽象词抽掉，看句子还立不立得住 |
| **跳步** | A 直接到 C，中间的 B 消失了；因果链断开（“然后就有了……”） | 在每两个论断之间插一个“为什么”，插不进去就是跳了 |
| **绕过去** | 其实在背原话，不是自己的话；靠重复术语糊过关键点；一问“为什么”就断 | 问一句“换个说法再讲一次”；或问“如果 X 变了呢” |

输出格式（表格，直接给用户看）：

```markdown
| 你说的 | 类型 | 问题在哪 |
|---|---|---|
| “它会自动调整……” | 跳步 | 谁在调、依据什么信号，这中间少了驱动机制 |
| “这个东西很重要” | 含糊 | “这个东西”指的是哪一步？ |
```

**注意反面**：如果用户讲得确实好，不要为了显得严格而硬找毛病。这种情况直接进入“边界测试”（下面），而不是继续磨。过度挑刺会让学习者丧失表达意愿。

## 第二轮：只补漏洞

纪律：**只讲你标出来的那几条，不重讲全部**。重讲全部是偷懒——它看起来负责，实际上把用户已经会的部分又倒一遍，且稀释了真正的缺口。

每条补漏必须包含三样：
1. **一个不一样的说法**（同一句话再说一遍没用，换个角度/换一个类比）
2. **为什么你会在里卡**（通常不是笨，是缺一个前置概念，把那个补上）
3. **一个小检验**（“你现在如果用一句话说这个，会怎么说”）

补完马上回到复述：“再讲一次，只讲刚才那几处。”

## 什么时候算通过

三个判据全部满足：

- **简单**：一个不了解背景的人能听懂，没有未解释的术语
- **准确**：没有错误，也没有过度简化造成的失真（边界还在）
- **完整**：关键因果链齐了，能回答“为什么”而不只是“是什么”

**通关仪式（必做）**：给一个反问——“那如果 X 呢？”（X 是一个边界情形）。用户能接住，就正式通过；接不住，就恰好找到了下一轮要补的点。

**防无限循环**：最多四轮。四轮还不过，说明问题不在表达，在**前置知识缺失**——停下来直说：“你卡的不是这个概念的表述，是更底下的 X。我们先把 X 补上，回来这里会很快。”继续磨下去只会产生挫败感，不会产生理解。

## 收尾

把用户最后那版解释整理成一段话（用他的词，不是你的），再给三样：

- 一句话版本（能一口气说完的那种）
- 你现在能把它讲给谁听（具体到场景/对象）
- 下一个该讲的东西（只一个）

## 输出模板

```markdown
## 第一轮：讲给 12 岁
<250–400 字，一个例子，一个边界>

> 现在用你自己的话讲一遍，不用完美，我要找的是你卡住的地方。
```

用户复述后：

```markdown
## 诊断
| 你说的 | 类型 | 问题在哪 |
|---|---|---|

## 只补这几处
**1. <漏洞>**
- 换个说法：……
- 你为什么会卡：……
- 小检验：……

> 再讲一次，这次只把这几处说顺。
```

通关：

```markdown
## 通过
你的版本（整理后）：……
一句话版：……
你能讲给：<谁>听
下一步：<一个>
```

## 质量红线

- **不许跳过复述环节**。没听到用户自己的话，就不能判断他懂没懂。
- **不许笼统反馈**。每条必须引原句、指位置。
- **不许重讲全部**。只补漏洞；重讲全部会稀释真正的缺口。
- **不许用同一说法重复**。第二遍必须换角度，否则只是声音大了一点。
- **类比必须讲明哪里不像**。不标注边界的类比会留下错误直觉，比不讲更坏。
- **不许空表扬代替诊断**。“很好”“很棒”一律换成具体到句子的观察。
- **不许为了严格而硬找毛病**。讲得对就用边界测试验证，不要刁难。
- **四轮不过必须停**。指出前置知识缺口，而不是无限制磨。
- **没过之前不开新内容**。用户想跳也不能跳，这是整个方法的纪律。

## 与其他技能的分工

- 并行：`five-expert-interview`（测你会不会说 vs 测你能不能说清）
- 上游：`five-expert-sprint` / `five-expert-levels`（先学一轮，再来磨）
- 下游：能把 X 讲清楚了，就进入下一个概念；或去 `five-expert-curator` 找下一轮资源
