# 一页速查表（Cheat Sheet）

`five-expert-panel` 技能组的第十棒。它不用于学习，用于**上场前 5 分钟**。

判断标准只有一条：用户拿这张表在做事的现场翻 30 秒，能不能找到一个能直接用上的东西。找不到，就是写成了笔记，不是速查表。

与组内其他学习类技能的区别：

| 技能 | 场景 |
|---|---|
| `five-expert-sprint` | 从零到能用，2 小时 |
| `five-expert-levels` | 系统变强，一至六个月 |
| `five-expert-curator` | 找资源，一周 |
| **本技能** | **马上就要用，5 分钟** |

## When to Use（何时用）

- 用户说“做份速查表”“上机前过一遍”“考前最后看什么”
- 已经学过一轮，需要一件手边工具
- 团队共享的操作要点、API 速查、流程提醒卡

不适用：还没学过（先学）；要理解而不仅是要用（用费曼或分级）。

## 硬约束：“一页”是真实物理限制

中文 **800–1200 字**（含表格），超过就不是速查表。这一条比所有写作技巧都重要——内容超出这个预算，用户就不会在临上场前翻它。

写作时的自动反应：想补一句解释时，问自己“他当场会用上这句吗”，用不上就删。

## 六个区块，各有判据

### 1. 一句大白话定义

一句话，**40 字以内**。要回答“这东西是干嘛的、什么时候用它”，不是教科书定义。

- ❌ “X 是一种基于……的方法论，广泛应用于……”（这是摘要）
- ✅ “当你需要把一堆零散数据变成能拍板的一句话时，用它”

硬规则：定义里不得出现被定义的词本身，不得出现未解释的术语。

### 2. 核心条目（表格/列表，不许长段）

拆成三小块，能多短就多短：

- **关键概念**：名词 + 一句人话（≤20 字）
- **规则/公式**：公式必须同时给「什么时候用」+「变量是什么意思」；否则公式是装饰
- **步骤**：编号，每步一个动作，动词开头

任意一条超过 3 行就该拆。发现自己在写“首先……其次……最后……”的段落，就是失败了。

### 3. 真实场景例子（3–5 个）

每个一句话：**场景 → 用哪条规则 → 结果**。

关键约束：**至少有一个反例**——“看起来像，但其实不适用这个”。这是速查表与教程最大的差别：教程只告诉你什么时候对，速查表要防止你用错场合。

### 4. 新手错误与易混点

- **错误**：错误名 + 症状（怎么发现自己正在犯） + 一句改法
- **易混**：两个概念 + 一句话区分法（“X 看的是 A，Y 看的是 B”）

只写症状不写改法 = 只负责吓人；“注意细节”这类话直接删。

### 5. 上场前检查清单

5–8 条，可勾选。每条必须是**当场能验证的事实**，不是心态提醒。

- ✅ `[ ] 输入数据的日期范围是不是本月`
- ❌ `[ ] 保持冷静、仔细检查`

验收标准：真到了现场，30 秒能走完一遍。

### 6. 5 个快问快答

一问一答，答案 ≤2 行。题型配比固定：

| # | 题型 |
|---|---|
| 1 | 定义（用它自己的话） |
| 2 | 规则应用（给一个数/场景问结果） |
| 3 | 易混辨析 |
| 4 | 数值/默认值/单位 |
| 5 | 场景判断（该不该用） |

**自包含约束**：五道题的答案必须**全部能在表内找到**。速查表不能靠外部资料才能用。

## 输出模板

```markdown
# <主题> 速查表

> 一句话：<40 字内，干什么用的>

## 核心
| 项 | 一看就懂 |
|---|---|
| 概念 | …… |
| 公式/规则 | <公式>（何时用：……；变量：……） |
| 步骤 | 1. …… 2. …… 3. …… |

## 三个场景
- 场景：…… → 用：<规则> → 结果：……
- 反例：<看起来像但不适用> → 应该：……

## 别踩这些
- **<错误名>**：症状…… → 改法……
- **易混**：A vs B → 一句话区分……

## 上场前
- [ ] ……
- [ ] ……

## 快问快答
1. **Q**：……　**A**：……
```

## 好坏怎么验

把这张表给一个不了解该主题的同事，让他读 5 分钟，然后请他做一件具体的事。做出来了，表合格；他问“这个是什么意思”，那一处就要重写。

## 质量红线

- **超字数就是失败**。800–1200 字封顶，宁少不多。
- **不许长段落**。超 3 行就拆，出现“首先其次最后”就是写成了文章。
- **不许自我引用**。“详见上文”“参见第 3 节”这类链接在速查表里无意义，表必须自包含。
- **公式必须带使用场景**。光给公式不给“什么时候用”，等于给了一把没柄的刀。
- **例子必须有反例**。只有正面案例会让人在错误场合用对方法。
- **清单必须可勾选**。写“注意安全”不如写“阀门关到底”。
- **快问快答的答案不得引入表外信息**。否则它测的是记忆，不是这张表。
- **不许为了凑字而堆术语**。术语密度高不等于信息密度高。

## 与其他技能的分工

- 上游：`five-expert-sprint` / `five-expert-levels`（先学过，再来压）
- 本技能：把已学内容压成手边工具
- 下游：临场使用；用完发现哪里不够，回 `five-expert-feynman` 把那一块磨顺
